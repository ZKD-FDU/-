# Phase 0 Assumptions

## Source Materials

- `CODEX_IMPLEMENTATION_BRIEF_HongCe.md` is treated as the binding engineering instruction.
- `HongCe_full_social_simulation_proposal.docx` is treated as the product and research proposal.
- The DOCX has been extracted to `work/HongCe_full_social_simulation_proposal.extract.md` for auditability.

## Workspace

- The current workspace was effectively empty at start: only `work/` and `outputs/` existed.
- The directory is not a Git repository, so there were no tracked or uncommitted source changes to protect.
- Stage 0 initializes a new project structure in the current workspace.

## Runtime

- Core implementation will run without external model keys or network access.
- Python is the authoritative simulation runtime for S0/S3/S5 MVP.
- Current bundled Python has `pydantic`, `numpy`, and `pandas`; `pytest`, `networkx`, and `fastapi` are not currently installed.
- Until API-stage dependency installation is explicitly handled, Phase 0 tests use standard-library `unittest`.

## Modeling

- `FACT` values are only public-source anchors and cannot become direct real-world predictions.
- `SYNTHETIC` values define Qingyuan county, virtual people, facilities, networks, and policy parameters.
- `SIMULATED` values must be generated by actual simulation runs with fixed seeds.
- LLM/YuLan integration is optional and must be swappable. Safety-critical flood progression, facility failure, capacity, route availability, dispatch constraints, harm risk, and metrics remain deterministic code.

## MVP Defaults

- First end-to-end MVP prioritizes S0, S3, and S5.
- Default synthetic resident count is 2,000 for MVP; the architecture should allow 5,000.
- Crisis timestep is 5 minutes.
- The state chain is frozen as: `uncontacted -> contacted -> confirmed -> waiting_transfer -> in_transit -> sheltered`, with explicit failure and delay states.
- Same-scenario policy comparisons must reuse the same population, network, hazard trajectory, and seed set, changing only `PolicyConfig`.
