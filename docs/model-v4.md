# 洪策 v4：位置连续的车队与可核对的县域沙盘

2026-09-11。本轮从策划书的“谁先转、资源怎样到位、为什么错过窗口”出发，修正车队空驶假设，增加可比较的群体调度规则，并让地图、车辆、人员和安置记录使用同一份事件数据。模型版本为 `hongce-positioned-kernel-v4`。

## 从同类项目采用的设计

本表为查阅项目 README 和官方文档后的设计归纳，不表示已经集成这些软件；本轮代码独立实现，未复制第三方模型源代码。

| 一手资料 | 值得采用的做法 | 本轮落地 | 尚未实现的部分 |
|---|---|---|---|
| [Newcastle FIRM2](https://github.com/nclwater/FIRM2) | 将洪水、地形、道路、建筑与车辆行动相连，处理道路受阻 | 车辆保存驻地与下一可用位置；接人和载客分别选择可行通行窗口 | 未接入地形栅格、水动力和真实交通需求；未复制该项目验证结论 |
| [SUMO 动态路由](https://sumo.dlr.de/docs/Simulation/Routing.html) | 旅行时间随时间变化，关闭道路后重新计算路线 | 空驶可经过多个走廊；双向通行共享分时容量；加载前核对后续载客窗口 | 没有跟驰、路口信号、私家车交通；不承诺非 FIFO 条件下全局最优 |
| [Mesa 数据采集](https://mesa.readthedocs.io/stable/apis/datacollection.html) | 区分模型汇总、个体属性和事件表 | 分组累计安置曲线来自个体实际到达时刻；车辆分段记录和逐次实验 CSV 可核对 | 仍使用现有轻量内核，未迁移至 Mesa |
| [Geoscience Australia ANUGA](https://github.com/GeoscienceAustralia/anuga_core) | 地形网格及边界条件下求解浅水方程 | 明确把预设路段水深与真实水动力求解分开 | 未接入 ANUGA；需实测 DEM、流量/水位边界与独立校验数据 |
| [University of Saskatchewan flood_abm](https://github.com/uofs-simlab/flood_abm) | 将组织和不同人群置于地理场景中 | 保留脆弱/普通应转人群、机构准备与授权，不把全体对象设为同一种行动者 | 不将示例项目架构当作现实可靠性证据 |

## 车队如何行动

1. 车辆首次位于 `fleet_base_id`，默认北岸中学。派车前计算该位置到接人点的空驶路径。无可行路径时继续等待，不让车辆直接出现在目标处。
2. 空驶到位后装载；同车人员来自同一接人点、使用同一路线和安置点。照护、担架、车辆容量及安置名额必须同时满足。
3. 每条走廊记录半开预约区间 `[进入分钟, 离开分钟)`；两方向共享并发容量。同一分钟一车离开后另一车可进入。装载和卸载不占道路容量，但持续占用车辆、照护及担架资源。
4. 对整次载客行程检查预设水深过程线、积水减速和封闭时刻。使用 v3 的减速公式与阈值假设，见 [v3 方法](model-v3.md)。不把默认水深阈值当作现实车辆涉水标准。
5. 到达才计入实际安置。卸载完成后，车辆位于该安置点，下一次任务从这里空驶；不强制先返回原接人点，也不能同时接到另一批任务。
6. `transport.trips` 保存派车地点、派车/到位/载客出发/到达/释放时刻、乘员和分段路径；`road_reservations` 可独立检查每条路的容量。前端车辆沿这些记录运动，待命车数由上一任务终点和释放时间计算。

下列简化仍然重要：空驶路由为简单路径的时间标签搜索，不包含中途主动等待；未来积水视为已知情景，未处理预报误差与突发道路破坏；载客只在起点可用的直达走廊中选择目的地。不同走廊在地图上相交，并不自动形成可转向路口。照护与担架采用任务资源池，尚未跟踪每名工作人员和物资的具体位置。车库、司机轮班和异型车辆尚未建模。

## 公平策略的定义

默认 `dispatch_mode=policy_priority` 延续政策中的脆弱性与等待提权规则。新增 `balanced_coverage` 是可选择的对照方案，不是自动推荐：

`群体已派车覆盖率 = 该群体已分配乘员数 / 当前已知且获授权的应转请求数`。

每次选择下一辆车的任务时，先考虑覆盖率较低的群体，同组按等待时刻排序，再检查通行与照护约束。同车仍受同起点限制。分母只包含已进入待转队列的对象，不使用尚未触达的全知名册。它均衡的是已知请求分配，不直接保证最终安全率相等，也不能弥补总运力不足。

比较时须同时查看总体、脆弱与普通应转人群，并核对预算是否相同。即使普通群体得到改善，也不能省略脆弱群体可能下降的代价。最终结论见 [v4 验证结果](validation-v4.md)。

## 前端空间真实性的边界

本轮遵照视觉回退要求，以 `75d76bb` 的初步修改版本为界面依据，保留原 `styles.css`、深蓝指挥舱和数据仪表盘。撤销替代三维视图的 SVG 地图设计，使用原 Three.js 技术路线；同版本 Three.js 0.160.0 与 MIT 许可证存入 `web/vendor/`，避免 CDN 不通时三维画面空白。

地图中地点、河网与主走廊读取项目空间包；空间包本身标记为合成。地形由坡面、平滑山丘和河床切槽组成连续网格，补齐地形侧壁、设施场地整平、河岸与河床水面。道路有宽度、路肩和标线，跨河段设桥面、护栏和桥墩；村落坡屋顶、城镇多层建筑、养老院院落、医院、学校操场和体育馆使用不同结构。建筑、树木和地形起伏为合成表现，建筑数量不是人口统计值。院落门口和支巷是制图背景，未进入车流路由。

标签改为固定屏幕字号，按当前视角避让；窄屏无法同时容纳的标签会隐藏，仍可从对象选择器访问。点击设施可检查数据并定位近景，鼠标拖动旋转、滚轮缩放、按钮复位；图层与时间控制移出画布，避免挡住建筑。水文标签打开路段积水过程线，预案入口接回原复盘视图。三维车辆、路段和建筑可点击检查。

道路状态、积水数值、车辆轨迹、机构待转人数与床位到达/预留数来自实际仿真。积水图层为固定宽度的路段状态带，不伪造二维淹没范围。回放时刻只改变观察切片，不修改仿真结果。参数变更后标记待重跑，保留上次运行所用配置。群体曲线按各组应转人数为分母，由实际安置时刻累加。

因此本轮是可检查的空间政策沙盘，不是实景三维数字孪生。提升现实有效性下一步应优先接入真实道路和车库、机构转移演练时间，再接 DEM、水文边界与洪水观测；不能通过增加建筑模型数量替代数据校准。

## 对照策划书的完成度

| 策划书目标 | 当前状态 | 后续验收需要 |
|---|---|---|
| 多层关系、有限认知与组织授权 | 已有延迟、失败、人工确认容量与准备过程；规则参数未校准 | 演练记录中的信息与授权时间、抽样行为问卷 |
| 脆弱性、资源与公平 | 两组指标、实际车辆位置、资源约束与两种派车规则已连通 | 异型车辆、照护随车人员、家庭共同转移、分诊队列 |
| GIS 沙盘与事件追溯 | 原风格三维地形、路网、车辆和个体记录联动；支持专注模式及设施定位 | 实测地物、共享路段/交叉口拓扑、逐建筑风险输入 |
| A/B/C 与压力实验 | 版本化、共同随机种子、区间和逐次 CSV；负向结果保留 | 独立历史或演练验证；拟合与留出数据严格分离 |
| 七幕情景、政策学习、真实校准 | 当前主要覆盖灾前预警至紧急转移；未完成长期安置及训练闭环 | 持续预算、灾后安置、跨事件验证；不能称已训练强化学习 |

当前应转范围仍按合成地点与个人脆弱性规则定义，并非逐建筑水深实时生成。实验的随机种子重复检验的是模型内稳定性，不是现实预测准确率。
