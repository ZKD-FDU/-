# 洪策 MDP/POMDP、政策优化与强化学习设计

## 目标

洪策的强化学习路线不直接训练黑箱智能体，而是先把灾害转移问题定义为可验证的决策环境，再用可解释参数优化得到政策组合，最后逐步引入 Contextual Bandit、Constrained RL 和多智能体 RL。

## MDP/POMDP 定义

- State：当前分钟、雨洪风险等级、通信失败率、桥梁状态、各地点待转移人口、脆弱人口、车辆/床位/照护资源余量、公众信任度。
- Action：发布预警、升级响应、车辆派往具体地点、养老机构优先、桥涵关闭或绕行、启用备用避难点、加派网格叫应。
- Reward：安全转移率、脆弱群体伤害风险、风险有效提前量、资源排队时间、群体公平缺口、漏管关键动作、公众信任变化。
- Transition：复用 `hongce.engine.run_policy`，每个候选政策必须经过实际多智能体仿真运行。
- Constraint：约束脆弱群体风险、群体公平缺口、安全转移率、资源排队时间。

## 第一阶段：可解释政策参数优化

已实现：

- `GET /decision/mdp`：返回 MDP/POMDP 合约。
- `POST /decision/optimize`：对预警提前量、转移命令提前量、车辆倍率、脆弱人群优先权重、桥涵阈值、通信补救强度进行网格/随机搜索。
- 每个候选组合都调用真实仿真内核，不使用固定演示数据。
- 输出最优组合、平均指标、奖励、约束违背。

## 第二阶段：Contextual Bandit

已实现：

- `POST /decision/bandit`：比较提前预警、增加车辆、养老机构优先、备用通信、桥涵绕行等动作臂。
- 对每个动作臂进行仿真评分，并用约束惩罚排序。
- 输出推荐动作、期望奖励、指标均值和约束情况。

## 后续升级

- 贝叶斯优化：替代或补充网格搜索，用更少仿真次数搜索连续参数。
- DQN/PPO：将动作拆成多时间步连续调度，但动作空间必须先离散化并保持较小规模。
- Constrained RL：将伤亡率、脆弱群体公平、资源约束作为硬约束或拉格朗日惩罚。
- Multi-Agent RL：把应急局、街镇、村居、机构负责人、群众拆成多个主体，作为最后阶段。

## 校准与验证

- 应急管理部报告案例：校准参数范围和失败模式。
- QGIS 空间包：校准路线、桥涵暴露、风险区覆盖和避难点容量。
- 专家核对：校准致灾因子和洪涝风险参数。
- 对比实验：S0-S5 与优化/RL 推荐策略比较。
- 消融实验：去掉网格叫应、脆弱优先、QGIS 空间约束、通信失败。
- 不确定性分析：改变雨强、通信失败率、车辆数量、群众响应率。
